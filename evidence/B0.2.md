## Docker Desktop rehearsal

Docker Desktop 4.57.0 ran its Linux AMD64 engine with Docker 29.1.3 and Compose 5.0.1. The first build attempt exited 1 because the Docker Desktop Linux engine pipe was missing. Opening Docker Desktop restored the engine, and the same build command then exited 0. The Linux Compose v2.40.3 standalone validator also exited 0 for `docker-compose --env-file .env.example config --quiet`.

The following commands ran from WSL with the Windows Docker CLI. Each exited 0 in the completed rehearsal. `FIELDBOOK_HTTP_PORT=18084` was passed to the Windows CLI via `WSLENV`.

```sh
docker.exe compose --env-file .env.example -p fieldbook-b02-rehearsal config --quiet
docker.exe compose --env-file .env.example -p fieldbook-b02-rehearsal build web
docker.exe compose --env-file .env.example -p fieldbook-b02-rehearsal pull db
compose() { docker.exe compose --env-file .env.example -p fieldbook-b02-rehearsal "$@"; }
compose up -d --wait db
compose up -d web
compose exec -T web curl -sS --max-time 5 -w '|%{http_code}' http://127.0.0.1:8080/healthz
compose exec -T web curl -sS --max-time 5 -w '|%{http_code}' http://127.0.0.1:8080/readyz
compose run --rm web fieldbook migrate
compose run --rm web fieldbook migrate
compose exec -T web curl -sS --max-time 5 -w '|%{http_code}' http://127.0.0.1:8080/readyz
docker.exe image inspect "$(compose images -q web)" --format '{{.Os}}/{{.Architecture}} {{.Config.User}}'
compose exec -T web id -u
compose port web 8080
curl.exe -fsS --max-time 5 http://127.0.0.1:18084/readyz
printf '%s\n' "INSERT INTO households (label) VALUES ('Fixture household A') RETURNING id;" |
  compose exec -T db psql -XAtq -v ON_ERROR_STOP=1 -U fieldbook -d fieldbook
printf '%s\n' 'B0.2 fictional media marker' |
  compose exec -T web sh -c 'cat > /var/data/fieldbook/rehearsal.txt'
compose stop db
compose exec -T web curl -sS --max-time 5 -w '|%{http_code}' http://127.0.0.1:8080/healthz
compose exec -T web curl -sS --max-time 5 -w '|%{http_code}' http://127.0.0.1:8080/readyz
compose down
compose up -d --wait web
compose exec -T web curl -sS --max-time 5 -w '|%{http_code}' http://127.0.0.1:8080/healthz
compose exec -T web curl -sS --max-time 5 -w '|%{http_code}' http://127.0.0.1:8080/readyz
printf '%s\n' "SELECT id || '|' || label FROM households WHERE id = '5612cc06-7f40-489c-92e0-9ad7c9dca468';" |
  compose exec -T db psql -XAtq -v ON_ERROR_STOP=1 -U fieldbook -d fieldbook
compose exec -T web cat /var/data/fieldbook/rehearsal.txt
compose down --volumes
```

The release image was `linux/amd64` with configured user `10001:10001`. The running web container reported UID `10001`. Its Windows host loopback publication was `127.0.0.1:18084`. Health returned 200 throughout, while readiness returned 503 before migration and during the database outage. Readiness returned 200 after migration and after both containers were recreated. After `compose down` and `compose up`, PostgreSQL returned the same fixture UUID `5612cc06-7f40-489c-92e0-9ad7c9dca468` and the private media volume retained its text marker. Cleanup removed only the disposable project's containers and volumes.

Other architectures, TLS and LAN access, hosted profiles, and the full T0 rehearsal remain untested. The packet self-test, native PostgreSQL run, and Docker Compose rehearsal are distinct results.
