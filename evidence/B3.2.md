## Browser observations

- Two separate Chromium contexts signed in with independent virtual passkeys. In the words-first flow, the learner saved a sentence. The guardian opened **Family photos to match**, used **Choose photos** with the keyboard, set an activity date, and saved a JPEG. The first upload response was dropped after PostgreSQL committed 1,151 of 2,302 bytes. The same Save button resumed at 1,151 and published one verified asset.
- The learner opened the moment and used Enter on **Match practice-photo.jpg**. Two repeated requests, including one from the guardian, returned 204 and left one link with the original matcher. **Unmatch** returned the photo to the inbox with the same ID, bytes and uploader. A repeat unmatch returned 204. Relinking the original retained its uploader. The moment's audit held three transitions with no replay duplicates.
- The photo-first adapter saved the JPEG before the learner wrote the moment. It observed one new original, one link before unmatch, zero links afterward, and the original guardian uploader and hash. The normal suite also used **Choose a file** for a PDF before a moment and attached an MP4 directly from the guardian's view of that family moment. The PDF stayed first and the MP4 had the guardian's match attribution.
- Matching an already matched file to another moment returned 409. A guardian POST against a synthetic diary row returned 404 and added no relation. Its attachment metadata returned 404. The test temporarily admitted a diary visibility value in the disposable database to exercise a real row ID before the diary creation ticket. A different household received 404 for the inbox and match, and a learner mutation without CSRF returned 403.
- Migration 0006 upgraded a five-migration database. The pre-existing synthetic asset `f7e628e9-69da-46af-895a-011700b33201` retained position 0, its original byte count and the fixture digest. Existing relations receive a null matcher.
- The independent reviewer checked household, learner and uploader scope, family-only locking, competing mutations, migration behavior and creation replay. The final review confirmed that the same transaction audits match and unmatch and that creation replay preserves its initial asset list.

## Scope and remaining observations

The inbox identifies files by name, uploader and optional activity date. The picker accepts one file per save, up to 64 MiB, and retains the transfer key for an in-page retry. The browser verification used virtual passkeys and separate contexts on one computer. Physical Android, Google Photos picker integration, multi-device hardware, large files and sanitized image previews are untested. The inbox project field awaits the project model. B3.3 and full T3 remain pending, including opening four archived files with Drive unavailable and promoting a link-only recording.
