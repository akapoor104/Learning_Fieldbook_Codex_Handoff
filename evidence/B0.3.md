## Local Docker and PostgreSQL rehearsal

The first run built the release but exited 1 because Docker Desktop rejected a colon in the simulated socket mount target. A local socket directory without colons resolved that test-harness limitation. The cloud configuration retains Google's managed `/cloudsql/PROJECT:REGION:INSTANCE` path.

The following commands use the named project `fieldbook-b03-rehearsal`, fictional credentials from `.env.example`, and a temporary Compose override. The override gives PostgreSQL a named volume at `/var/run/postgresql` and mounts it into web at `/cloudsql/fieldbook-db`. It sets `POSTGRES_INITDB_ARGS=--auth-local=scram-sha-256` and publishes PostgreSQL on an automatically chosen local port for the Rust integration test.

```sh
export FIELD_IMAGE=fieldbook:b03-rehearsal FIELDBOOK_HTTP_PORT=18083
compose() {
    docker compose --env-file .env.example -p fieldbook-b03-rehearsal -f compose.yaml -f /tmp/fieldbook-b03-rehearsal.yaml "$@"
}
psql_fixture() {
    compose exec -T db sh -c 'PGPASSWORD="$POSTGRES_PASSWORD" psql -XAtq -v ON_ERROR_STOP=1 -h 127.0.0.1 -U fieldbook -d fieldbook "$@"' sh "$@"
}
probe() {
    compose exec -T web curl --retry 5 --retry-connrefused --retry-delay 1 -sS --max-time 5 -w '|%{http_code}' http://127.0.0.1:8080/healthz
    compose exec -T web curl -sS --max-time 5 -w '|%{http_code}' http://127.0.0.1:8080/readyz
}
compose config --quiet
docker compose --env-file .env.example -p fieldbook-b03-rehearsal build web
compose up -d --wait db
compose up -d --no-build web
probe
compose run --rm --pull never web fieldbook migrate
socket_url='postgres://fieldbook:disposable-b02-smoke@localhost/fieldbook?host=/cloudsql/fieldbook-db&sslmode=disable'
compose run --rm --pull never -e DATABASE_URL="$socket_url" -e FIELD_ENV=production web fieldbook migrate
probe
docker image inspect "$FIELD_IMAGE" --format '{{.Id}} {{.Os}}/{{.Architecture}} {{.Config.User}}'
psql_fixture -c 'SHOW server_version;'
psql_fixture -c 'SELECT version, success FROM _sqlx_migrations;'
fixture_id=$(psql_fixture -c "INSERT INTO households(label) VALUES ('Fixture household A') RETURNING id;")
printf '%s\n' 'B0.3 fictional media marker' | compose exec -T web sh -c 'cat > /var/data/fieldbook/rehearsal.txt'
compose stop db
probe
compose down
compose up -d --wait --no-build web
probe
psql_fixture -c "SELECT id || '|' || label FROM households WHERE id='$fixture_id';"
compose exec -T web cat /var/data/fieldbook/rehearsal.txt
```

Both migration invocations printed `Fieldbook migrations applied` and the migration query returned exactly `1|t`.
