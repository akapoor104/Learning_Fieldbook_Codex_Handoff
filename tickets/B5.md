# B5 · Relatives and outside feedback

Design v0.8 · Acceptance T5 · Primary lane access

Use one named relative and one withdrawn grant.

## Outcome

Per-entry invitation, preview of chosen text/files, comments and revoke. Separate family-uploaded teacher letter from parent paraphrase.

## Read only what you need

Use the numbered paragraphs in `reference/Learning_Fieldbook_Design_Spec_v0.8.md`, lines 106-138,445-458. Shared API decisions are in `contracts/README.md`. Scenarios S3, S8, S12, S14.

## Assign one slice

### B5.1 · Approve exact guest material

**Suggested change area** Rust. **Prerequisites** B3.3, B4.1.

Persist an authenticated named guest’s grant to selected text revision and file representation, then support withdrawal.

**Inputs and suggested files** fixtures/household.json. crates/fieldbook/src/ and crates/fieldbook/tests/, plus web/src/ for a joint UI slice.

**Run** Run cargo fmt --all -- --check and cargo test --workspace --locked. For a UI join also run the relevant web tests.

**Passing example** The invited account may open the selected highlight and photo and see the intended attribution.

**Counterexample** An unrelated account, an unselected letter and a private diary remain unavailable.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B5.2 · Preview and comment as a relative

**Suggested change area** UI. **Prerequisites** B5.1.

Provide matched learner/guardian review, guest preview and dated comments. Keep teacher uploads and paraphrases distinguishable.

**Inputs and suggested files** fixtures/household.json. web/src/ and web/tests/.

**Run** From web/, run npm run check, npm test and npm run build. Exercise the named control with a keyboard.

**Passing example** A valid guest can add a comment to the selected highlight. Family archive records the writer and recorder.

**Counterexample** Adding an attachment or changing the source never expands an existing grant automatically.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B5.3 · Exercise revocation everywhere

**Suggested change area** QA. **Prerequisites** B5.2.

Withdraw the grant, repeat the real read, download and comment flows, and inspect visible lists.

**Inputs and suggested files** fixtures/household.json. The relevant integration or device tests and their evidence.

**Run** Drive the named application flow against a disposable fixture. Run the owning Rust or web suite plus the specified device or operator procedure.

**Passing example** Previously allowed guest access ends on each route and the household can still read its original.

**Counterexample** Reusing an expired invitation never makes an active grant or reveals a filename.

**Suggested model** GPT-6.2 Sol for the integration or review.

## Accept the complete ticket

**T5.** A relative can comment on the photo highlight. The same relative cannot open the unselected PDF, another entry or a private diary file. Revocation ends future app access. Teacher feedback comes through the family.

Runnable adapter cases in `validation/cases.json` include ‘guest-revoked’.

Record commands, actual outputs, test environment and evidence files. Attach the normal and adverse observations and the result of the full T case. An unchecked claim remains untested. Use `python3 tools/fieldbook.py template B5` to generate the pending receipt after implementation.
