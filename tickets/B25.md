# B25 · Project Failure Résumé and revival

Design v0.8 · Acceptance T25 · Primary lane product

Keep a per-project, learner-curated record of real setbacks. Preserve history through feature, unfeature, print and revival.

## Outcome

Generate the project résumé from selected real setbacks, support a print preview, and revive an attempt as a new linked pretotype.

## Read only what you need

Use the numbered paragraphs in `reference/Learning_Fieldbook_Design_Spec_v0.8.md`, lines 240-250,437-438,473-473,657-658,696-702. Shared API decisions are in `contracts/README.md`. Scenarios S23, S24, S26.

## Assign one slice

### B25.1 · Select setbacks and render one project

**Suggested change area** Rust. **Prerequisites** B24.3, B23.1, B22.2.

Project an actual missed prediction or reported unexpected setback, its lesson and optional pride note. Scope assets, sources and downstream build titles for the chosen reader. Store a reversible selection by stable observation revision.

**Inputs and suggested files** fixtures/project-trials.json. crates/fieldbook/src/ and crates/fieldbook/tests/, plus web/src/ for a joint UI slice.

**Run** Run cargo fmt --all -- --check and cargo test --workspace --locked. For a UI join also run the relevant web tests.

**Passing example** Re-adding an entry returns one selection. A build that otherwise worked can appear because an unexpected failure was actually recorded.

**Counterexample** Sample results, another project, and unselected or inaccessible evidence produce no résumé content or counts.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B25.2 · Print a résumé and revive one idea

**Suggested change area** UI. **Prerequisites** B25.1.

Provide an accessible project preview and Print or save PDF with clear titles, learner wording, dates and authorized linked decisions. Add Revive this idea with a changed condition that starts a new pretotype.

**Inputs and suggested files** fixtures/project-trials.json. web/src/ and web/tests/.

**Run** From web/, run npm run check, npm test and npm run build. Exercise the named control with a keyboard.

**Passing example** A learner can feature a miss, remove it and add it back. Its date and text stay intact after an independently dated successful revival.

**Counterexample** Empty projects show a short prompt. Printing creates no share. Handle long writing across pages; a stopped project still has a usable résumé.

**Suggested model** GPT-6 Luna for a bounded implementation or test.

### B25.3 · Restore and review the learning record

**Suggested change area** QA. **Prerequisites** B25.2.

Use schema 7 media and record backups to restore selected/unselected items, parked trials, revisions and source links. Run both-guardian recovery and changed guest-grant checks on the integrated application.

**Inputs and suggested files** fixtures/project-trials.json. The relevant integration or device tests and their evidence.

**Run** Drive the named application flow against a disposable fixture. Run the owning Rust or web suite plus the specified device or operator procedure.

**Passing example** Round-trip two prototypes that share P2 and a revived setback. Compare IDs, content revisions, selection state and result dates in the project and the printable rendering.

**Counterexample** Legacy schemas 1–6 create no fictional history. A missing endpoint or later revoked grant blocks release of the affected data. Unauthorized exports remain denied.

**Suggested model** GPT-6 Luna for a bounded implementation or test.
