# B11 · Hosting rehearsal

Design v0.8 · Acceptance T11 · Primary lane recovery

Label each hosting profile configuration-checked, live-tested, or untested.

## Outcome

Follow home-to-Render and home-to-Google recipes with the same synthetic dataset. Run the chosen target with a blank environment before moving family data.

## Assign one slice

### B11.1 · Rehearse the home installation

**Suggested change area** Ops. **Prerequisites** B0.3, B10.3.

Start a fresh home profile on synthetic records, simulate interrupted restore, recover and record the tested origin and image.

**Inputs and suggested files** fixtures/assets.json. deploy/, compose.yaml, render.yaml and the matching command or runbook.

**Run** Run docker compose --env-file .env.example config --quiet and the relevant profile-specific checks. Record actual and configuration-only runs separately.

**Passing example** Restarts retain files, identities and access history. A fresh-destination restore matches the manifest.

**Counterexample** A damaged archive fails before writes or cutover. Source remains available.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B11.2 · Validate the two hosted paths

**Suggested change area** Ops. **Prerequisites** B11.1.

Check Render Blueprint and Google Cloud Run, Cloud SQL and private Storage using the same release and fake records. Rehearse the selected target when authorized.

**Inputs and suggested files** fixtures/assets.json. deploy/, compose.yaml, render.yaml and the matching command or runbook.

**Run** Run docker compose --env-file .env.example config --quiet and the relevant profile-specific checks. Record actual and configuration-only runs separately.

**Passing example** Record exact release, configuration check and any actual rehearsal per host.

**Counterexample** Missing credentials or a paid target without authorization is recorded as untested or config-only, never deployed by default.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B11.3 · Rehearse one-writer cutover

**Suggested change area** QA. **Prerequisites** B11.2.

Document write drain, final verified export and switch. Rehearse the failure case before and after writes at the target.

**Inputs and suggested files** fixtures/assets.json. The relevant integration or device tests and their evidence.

**Run** Drive the named application flow against a disposable fixture. Run the owning Rust or web suite plus the specified device or operator procedure.

**Passing example** Before target writes the source resumes. After target writes newer data is frozen and verified before resuming one authoritative copy.

**Counterexample** A rollback that discards newer target writes fails the rehearsal.

**Suggested model** GPT-6.2 Sol for the integration or review.
