## Assign one slice

### B21.1 · Trash and restore a project

**Suggested change area** SQL. **Prerequisites** B15.2, B16.2, B17.2.

Implement soft-delete, the last-project empty state and restore with original project identity. Keep revision history and references together.

**Inputs and suggested files** fixtures/project.json. migrations/, crates/fieldbook/src/storage/ and SQL-backed integration tests.

**Run** Run cargo test --workspace --locked with an isolated PostgreSQL 16 database. Inspect committed rows and original file hashes where relevant.

**Passing example** Trash active, inactive and last projects. Reload and restore the same IDs without duplicate seeds.

**Counterexample** A stale open tab cannot edit a trashed project. Other projects keep shared references.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B21.2 · Recover a particular item

**Suggested change area** Rust. **Prerequisites** B21.1.

Retain branch or promoted children, previous parent/position, links, checks and source references in scoped recovery records.

**Inputs and suggested files** fixtures/project.json. crates/fieldbook/src/ and crates/fieldbook/tests/, plus web/src/ for a joint UI slice.

**Run** Run cargo fmt --all -- --check and cargo test --workspace --locked. For a UI join also run the relevant web tests.

**Passing example** Restore a removed subtree after an unrelated edit. Original IDs and prior history come back.

**Counterexample** A missing endpoint or occupied input remains pending with an explanation. Recovery does not overwrite unrelated edits.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B21.3 · Undo and redo a saved edit

**Suggested change area** UI/QA. **Prerequisites** B21.2.

Add reachable action pairs on keyboard, touch and context menu, plus persisted undo/redo receipts and redo invalidation.

**Inputs and suggested files** fixtures/project.json. The relevant integration or device tests and their evidence.

**Run** Drive the named application flow against a disposable fixture. Run the owning Rust or web suite plus the specified device or operator procedure.

**Passing example** Undo, reload, redo, then make a new edit. Only the applicable redo sequence survives.

**Counterexample** Changing authorization or a later conflicting edit prevents compensation without undoing someone else’s work.

**Suggested model** GPT-6.2 Sol for the integration or review.
