# B23 · Paper worksheet

Design v0.8 · Acceptance T23 · Primary lane access

Use the included sample sheet and a generic, non-STEM project.

## Outcome

Build the project/branch preview, pen-friendly print stylesheet, portable offline sheet and manual completion/reopen control.

Use the numbered paragraphs in `reference/Learning_Fieldbook_Design_Spec_v0.8.md`, lines 369-380,464-490,651-665. Shared API decisions are in `contracts/README.md`. Scenarios S18, S24.

## Assign one slice

### B23.1 · Select a printable plan

**Suggested change area** Rust. **Prerequisites** B15.2, B21.2.

Build one authorized projector for project/branch, saved outline order, stable paper references and optional in-scope notes or handoffs.

**Inputs and suggested files** fixtures/project.json. crates/fieldbook/src/ and crates/fieldbook/tests/, plus web/src/ for a joint UI slice.

**Run** Run cargo fmt --all -- --check and cargo test --workspace --locked. For a UI join also run the relevant web tests.

**Passing example** A collapsed branch includes saved descendants. Empty plan has three writable rows. Both endpoints must be in scope for a handoff.

**Counterexample** Unselected data, diary, letters, photographs, comments, history and removed records are absent.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B23.2 · Print or carry an offline sheet

**Suggested change area** UI. **Prerequisites** B23.1.

Render print preview, native Print or save PDF and one self-contained read-only HTML file. Provide writing lines and low-ink checkboxes.

**Inputs and suggested files** fixtures/project.json. web/src/ and web/tests/.

**Run** From web/, run npm run check, npm test and npm run build. Exercise the named control with a keyboard.

**Passing example** Check Letter and A4, a multipage 90-step plan and an offline file with the network disconnected. Long pages repeat project headings.

**Counterexample** A print from the private family workspace emits only the worksheet fields. A long label wraps and body controls do not print.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B23.3 · Re-enter paper marks safely

**Suggested change area** API/QA. **Prerequisites** B23.2, B21.3.

Find steps by printed stable code/title. Validate changed rows and revisions and save as one undoable, idempotent group. Clear a mark to reopen.

**Inputs and suggested files** fixtures/project.json. The relevant integration or device tests and their evidence.

**Run** Drive the named application flow against a disposable fixture. Run the owning Rust or web suite plus the specified device or operator procedure.

**Passing example** Rename and reorder after printing, then mark, reopen, undo, redo, repeat and restore a backup. IDs and completion state persist.

**Counterexample** A stale or removed row rolls back the batch. No marks produce a journal moment, a portfolio item or a passed handoff.

**Suggested model** GPT-6.2 Sol for the integration or review.

## Accept the complete ticket

**T23.** Print an arbitrary project, an empty plan, a collapsed branch and a multipage outline. Check order, page headings, Letter/A4 fit and absence of unselected records. Rename and reorder a step, then match the paper by code. Reopen it, undo/redo the batch, retry, restore a project backup, and verify zero extra evidence.

Runnable adapter cases in `validation/cases.json` include ‘print-branch’, ‘paper-retry’.

Record commands, actual outputs, test environment and evidence files. Attach the normal and adverse observations and the result of the full T case. An unchecked claim remains untested. Use `python3 tools/fieldbook.py template B23` to generate the pending receipt after implementation.
