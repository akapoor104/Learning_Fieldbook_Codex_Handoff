Single Docker release, PostgreSQL migration, readiness check, home Compose, Render Blueprint and Google profile from §7.

## Assign one slice

### B0.1 · Serve a health response

**Suggested change area** Rust. **Prerequisites** Ready from unpacking.

Create the smallest Rust workspace with an Axum router and a binary that binds the configured port. Add a loopback HTTP integration test.

**Inputs and suggested files** fixtures/household.json. Cargo.toml, Cargo.lock, crates/fieldbook/src/ and its router integration test.

**Run** Run cargo test --workspace --locked, start the actual binary, then request /healthz and an unknown route on loopback.

**Passing example** GET /healthz returns 200 and a status-only body from the running binary.

**Counterexample** An unknown route stays unknown. Logs and the response contain no connection strings.

**Suggested model** GPT-6 Luna for a bounded implementation or test.

### B0.2 · Persist the first migration

**Suggested change area** SQL. **Prerequisites** B0.1.

Add SQLx migrations on PostgreSQL 16, schema-aware /readyz, a non-root release image and a home Compose profile with persistent data.

**Inputs and suggested files** fixtures/household.json. migrations/, crates/fieldbook/src/storage/ and SQL-backed integration tests.

**Run** Run cargo test --workspace --locked with an isolated PostgreSQL 16 database. Inspect committed rows and original file hashes where relevant.

**Passing example** Insert a fictional record, restart app and database, and retrieve the same ID. The ready response is 200.

**Counterexample** With the database unavailable or the schema behind, /readyz reports unavailable while /healthz still serves.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B0.3 · Describe all three hosts

**Suggested change area** Ops. **Prerequisites** B0.2.

Add render.yaml and deploy/google with private media, secret references, migration and a readiness probe. Use the same image on every profile.

**Inputs and suggested files** fixtures/household.json. deploy/, compose.yaml, render.yaml and the matching command or runbook.

**Run** Run docker compose --env-file .env.example config --quiet and the relevant profile-specific checks. Record actual and configuration-only runs separately.

**Passing example** Validate Compose, Blueprint and Google configuration locally or in CI and record each result separately.

**Counterexample** Reject durable media on an ephemeral path. A configuration check cannot count as a paid-host rehearsal.

**Suggested model** GPT-6.2 Sol for the integration or review.
