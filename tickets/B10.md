Design v0.8 · Acceptance T10 · Primary lane recovery

Run only on disposable destinations using generated test keys.

## Outcome

Daily encrypted export, private diary protection, external-link inventory, fresh-instance restore and policy reconciliation.

## Assign one slice

### B10.1 · Export a consistent household snapshot

**Suggested change area** Storage. **Prerequisites** B4.3, B5.3, B9.2.

Serialize schema 6 manifest and immutable media under a consistent snapshot, encrypt for designated recovery recipients and publish the manifest last.

**Inputs and suggested files** fixtures/archive-vectors.json. migrations/, crates/fieldbook/src/storage/ and SQL-backed integration tests.

**Run** Run cargo test --workspace --locked with an isolated PostgreSQL 16 database. Inspect committed rows and original file hashes where relevant.

**Passing example** Six base moments, one separate highlight, four copied originals, one link and the frozen edition survive export.

**Counterexample** An absent blob or failed encryption cannot publish a success or replace a known-good backup.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B10.2 · Stage and validate restore

**Suggested change area** Rust. **Prerequisites** B10.1.

Decrypt and validate into an empty destination before activation. Verify IDs, byte length, SHA-256, link-only states and attribution.

**Inputs and suggested files** fixtures/archive-vectors.json. crates/fieldbook/src/ and crates/fieldbook/tests/, plus web/src/ for a joint UI slice.

**Run** Run cargo fmt --all -- --check and cargo test --workspace --locked. For a UI join also run the relevant web tests.

**Passing example** Open every copied asset after a clean restore and reconcile audit and newer revocations.

**Counterexample** A changed byte, missing object or unknown future schema leaves the live source untouched.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B10.3 · Recover with either parent

**Suggested change area** Ops/QA. **Prerequisites** B10.2.

Place synthetic keys under independent custody, re-enroll test users, run old-version migration vectors and document the last verified recovery.

**Inputs and suggested files** fixtures/archive-vectors.json. The relevant integration or device tests and their evidence.

**Run** Drive the named application flow against a disposable fixture. Run the owning Rust or web suite plus the specified device or operator procedure.

**Passing example** Either guardian independently restores. After re-enrollment a fresh logged action is required to view diary content.

**Counterexample** When revocation history freshness is unknown, prior external access remains inactive. No credentials or sessions are imported.

**Suggested model** GPT-6.2 Sol for the integration or review.

## Accept the complete ticket

**T10.** Restore originals, roles, provenance, recorded parental access, comments and old editions. Check file hashes, rebind accounts and confirm withdrawn grants/permissions remain withdrawn. Corrupt input leaves the live instance untouched.

Runnable adapter cases in `validation/cases.json` include ‘restore-corrupt’.

Record commands, actual outputs, test environment and evidence files. Attach the normal and adverse observations and the result of the full T case. An unchecked claim remains untested. Use `python3 tools/fieldbook.py template B10` to generate the pending receipt after implementation.
