# B22 · Permissions after recovery

Design v0.8 · Acceptance T22 · Primary lane access

Retest recovery with two households and a later withdrawal.

## Outcome

Carry removal records and grant revocations through archive export/import. Require the same permissions for each inverse.

## Read only what you need

Use the numbered paragraphs in `reference/Learning_Fieldbook_Design_Spec_v0.8.md`, lines 118-126,188-220,694-713. Shared API decisions are in `contracts/README.md`. Scenarios S10, S14, S21.

## Assign one slice

### B22.1 · Carry policy history through recovery

**Suggested change area** Rust. **Prerequisites** B21.2, B10.3, B5.3.

Merge the latest independently held revocations/audit with archived roles and remove stale access before publication.

**Inputs and suggested files** fixtures/archive-vectors.json. crates/fieldbook/src/ and crates/fieldbook/tests/, plus web/src/ for a joint UI slice.

**Run** Run cargo fmt --all -- --check and cargo test --workspace --locked. For a UI join also run the relevant web tests.

**Passing example** A grant withdrawn after the snapshot stays withdrawn after project and clean-instance restore.

**Counterexample** Unknown audit freshness leaves old external grants and export approval inactive until verified.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B22.2 · Test actor-specific inverse actions

**Suggested change area** QA. **Prerequisites** B22.1.

Run the role matrix against restored originals, thumbnails, counts, highlights and guest file access.

**Inputs and suggested files** fixtures/archive-vectors.json. The relevant integration or device tests and their evidence.

**Run** Drive the named application flow against a disposable fixture. Run the owning Rust or web suite plus the specified device or operator procedure.

**Passing example** Learner and authorized family can recover appropriate work. The former guest remains denied.

**Counterexample** Trying the same restore as a guest or unrelated household reveals nothing about the target.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B22.3 · Verify shared sources survive

**Suggested change area** Ops/QA. **Prerequisites** B22.2.

Recover a shared source and its archive with one project trashed and another active. Rehearse key custody and fresh parent access.

**Inputs and suggested files** fixtures/archive-vectors.json. The relevant integration or device tests and their evidence.

**Run** Drive the named application flow against a disposable fixture. Run the owning Rust or web suite plus the specified device or operator procedure.

**Passing example** The active project opens the identical source and attachments. The learner can see the access history.

**Counterexample** A recovery does not silently renew consent, grant a new audience or expose diary contents in the readable index.

**Suggested model** GPT-6.2 Sol for the integration or review.
