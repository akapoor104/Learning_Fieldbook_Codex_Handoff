Design v0.8 · Acceptance T17 · Primary lane product

A passing rehearsal and a passing integration are separate observations.

## Outcome

Validate a versioned sample and record real handoff and project integration evidence.

## Assign one slice

### B17.1 · Check a supplied sample

**Suggested change area** Rust. **Prerequisites** B16.2.

Validate a one-based beat pattern against a versioned agreement and distinguish structural validation from human judgment.

**Inputs and suggested files** fixtures/beat-pattern.json. crates/fieldbook/src/ and crates/fieldbook/tests/, plus web/src/ for a joint UI slice.

**Run** Run cargo fmt --all -- --check and cargo test --workspace --locked. For a UI join also run the relevant web tests.

**Passing example** Four cells and beats 1 and 3 produce Sample passed for this version.

**Counterexample** Beat 0 fails. A passing sample cannot become a checked-together result.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B17.2 · Record an actual integration

**Suggested change area** API. **Prerequisites** B17.1.

Pin real producer output, consumer revision, actor, criteria and result. Support a separate system-level observation.

**Inputs and suggested files** fixtures/beat-pattern.json. crates/fieldbook/src/ and crates/fieldbook/tests/, plus web/src/ for a joint UI slice.

**Run** Run cargo fmt --all -- --check and cargo test --workspace --locked. For a UI join also run the relevant web tests.

**Passing example** The consumer runs with real output and records Checked together with the exact revisions.

**Counterexample** Completing every subtask or a mock run alone cannot certify project success.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B17.3 · Invalidate affected checks only

**Suggested change area** QA. **Prerequisites** B17.2.

Change the producer contract and traverse actual dependent results while retaining prior revisions.

**Inputs and suggested files** fixtures/beat-pattern.json. The relevant integration or device tests and their evidence.

**Run** Drive the named application flow against a disposable fixture. Run the owning Rust or web suite plus the specified device or operator procedure.

**Passing example** Both affected consumers show Needs review. A separate branch keeps its prior valid status.

**Counterexample** Reopening older history preserves who checked it, the earlier version and the recorded result.

**Suggested model** GPT-6 Luna for a bounded implementation or test.
