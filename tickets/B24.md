# B24 · Pretotypes and cumulative prototypes

Design v0.8 · Acceptance T24 · Primary lane product

Start at project creation and keep hypotheses, observations and build decisions distinct. The same pretotype can guide several working versions.

## Outcome

Start each new project with a pretotype. Save predictions and observations separately. Link each prototype version to one or more observed trials and the learner’s rationale.

Use the numbered paragraphs in `reference/Learning_Fieldbook_Design_Spec_v0.8.md`, lines 223-238,437-438,470-472,656-658. Shared API decisions are in `contracts/README.md`. Scenarios S18, S25.

## Assign one slice

### B24.1 · Start the project with its first trial

**Suggested change area** Rust. **Prerequisites** B13.1, B15.1, B21.1.

Extend the normal project-create command to insert the first draft in the same transaction. Implement successive save-plan and record-observation commands. Use a human-authored plan, prediction, true observation date, learner attribution and expected revision.

**Inputs and suggested files** fixtures/project-trials.json. crates/fieldbook/src/ and crates/fieldbook/tests/, plus web/src/ for a joint UI slice.

**Run** Run cargo fmt --all -- --check and cargo test --workspace --locked. For a UI join also run the relevant web tests.

**Passing example** A new project returns a root and exactly one pretotype. A prediction exists before the user records the result.

**Counterexample** An exact retry creates one root and one draft. An older imported project opens with empty trials. A task tick cannot produce evidence.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B24.2 · Commit cumulative evidence links

**Suggested change area** SQL. **Prerequisites** B24.1.

Persist addressed observation revisions, prototype versions, rationale, test target and project-scoped many-to-many source rows. Authorize all body/path IDs before writing. Return forward and reverse links.

**Inputs and suggested files** fixtures/project-trials.json. migrations/, crates/fieldbook/src/storage/ and SQL-backed integration tests.

**Run** Run cargo test --workspace --locked with an isolated PostgreSQL 16 database. Inspect committed rows and original file hashes where relevant.

**Passing example** Three observed pretotypes allow V1 with P1/P2 and V2 with P2/P3. P2 retains one identity. A follow-up build pins the specific source revisions it selected.

**Counterexample** Reject drafts, duplicate or cross-project sources and a stale expected revision without committing a partial version. Replay an accepted request after checking current authorization.

**Suggested model** GPT-6.2 Sol for the integration or review.

### B24.3 · Walk from an observation to each build

**Suggested change area** UI. **Prerequisites** B24.2.

Open the first pretotype from New project. Display labels, plan/observe actions, a checkbox list with actual observations, a rationale and build test. Let an observed source open every build it informed.

**Inputs and suggested files** fixtures/project-trials.json. web/src/ and web/tests/.

**Run** From web/, run npm run check, npm test and npm run build. Exercise the named control with a keyboard.

**Passing example** A learner can cite a miss and an unclear trial, start two alternatives and create a version with one additional observation. Use only the keyboard for one pass.

**Counterexample** An empty state explains what to try. A suggestion or checkbox does not count as a real observation. Declined or parked projects stay findable.

**Suggested model** GPT-6 Luna for a bounded implementation or test.
